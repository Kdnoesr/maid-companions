## 1. 已经确认的物理事实

| # | 事实 | 证据 |
|---|------|------|
| F1 | `backdrop-filter` 采样的是元素**背后已绘制**的内容 | 多轮 headless 对照实验（`D:\DSH Workspace\_lg5\`） |
| F2 | 对**均匀色**做模糊/折射，结果仍是该均匀色 → 视觉上等于没做 | 同上；另有决定性实验：条子 z-index 0→5 渲染结果**逐字节相同**（0/2218800 字节差异） |
| F3 | 因此：挂在**不透明面板内部**的元素，其 backdrop 就是面板底色，**物理上不可能**产生可见玻璃 | 由 F1+F2 直接推出 |
| F4 | 输入框好看是因为它的 `background` 被设为 `transparent`，backdrop 直接是页面/立绘 | `lib/client.js` 中 `body[${OWNER_ATTR}] [data-composer-card] { background: transparent; }` |
| F5 | `mask-image` 打洞**无效**：给了 mask 后 `backdrop-filter` 整个失效 | 实测：无玻璃 127.5 / 整块玻璃 0.0 / 环带 mask 127.5（=无玻璃） |
| F6 | 面板必须保持中间可读、圆角与布局不被破坏 | 用户硬约束 +
  v0.2.3~v0.2.9 违规后被否 |

## 3. 待团队回答的关键问题

### Q1（dom-probe）设置窗面板的真实结构是什么？
- 面板类名 / 属性 / `role` / 祖先链 / `getComputedStyle().background` / `overflow` / `border-radius`
- `.wCInkW_panel` 到底存在吗？是 CSS Module 产物吗？有没有稳定的 `data-*` 锚点？

### Q2（adversary）镜像墙为什么在真机上无效？
按可能性排序待验证：
- 面板 `overflow:hidden` → `left:-160px` 的镜像墙被裁掉
- 祖先链有 `filter`/`transform`/`contain` → 制造 BackdropRoot，条子 backdrop 变成黑
- 条子 `z-index:-1/-2` 在面板建立堆叠上下文时被**画到面板背景之下**（被盖住）
- `installRing` 根本没被调用（选择器没匹配到面板）
- 插件代码没加载 / 没重启

### Q3（p1-designer）在 F3 这个死结下，什么样**能做出来**？
必须正面回答：既然面板内部采样不到面板外，那么「边缘有折射」只能靠
- 让边缘区域**真的能从面板外侧采样**（外部叠加层、或面板背景透明化+中间兜底），或
- 不用 backdrop，改用其它视觉手段（边框高光/内侧渐变）达到"像玻璃"

## 4. 纪律

1. **任何"修好了"的结论，必须先在真机结构上复现**，不能用 mock 近似。此前的失败全部源于 mock 与真机不一致。
2. 每条断言标注证据；无证据写「待验证」。
3. 不许修改 `lib/client.js`（Lead 统一改）；可以读、可以写实验。
4. 不许编造类名。任何 CSS Module 类名（形如 `_name_hash_N` 或 `wCInkW_xxx`）在写进规则前，必须先在真实产物里 grep 到命中。
